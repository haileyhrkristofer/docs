Do you want new employees to be automatically created in Okta when they are added to Hailey? With our Okta integration, this is possible – along with automatic synchronization of employee data and seamless user account management!

<Tip>
  First time activating one of **Hailey's standard integrations**? Start by reading [**THIS**](/haileys-standard-integrations) guide to know what to keep in mind before you get started.
</Tip>

## What does the integration do?

With the integration, data is automatically transferred from Hailey to Okta. If a value differs between the two systems, the value in Hailey will overwrite the corresponding value in Okta during the next synchronization. This reduces administrative effort, as you only need to maintain the information in Hailey.

The integration also enables automated user management. When a new employee is created in Hailey and a company email address is added to their employee profile, a user account is automatically created in Okta. If an employee no longer has an active employment in Hailey, you can also choose to have their Okta account automatically decomissioned.

## How does the integration work?

With API-based data transfer, Hailey and Okta are synchronized **every hour** based on detected changes. This means that:

- Any included data that differs between Hailey and Okta will be updated in Okta with the value from Hailey during the next hourly synchronization.

## What data is included?

The data that will be transferred to Okta is listed below. The data fields are synced hourly, from Hailey to Okta.

| **HAILEY** | **OKTA** |
| --- | --- |
| First name | First name |
| Last name | Last name |
| First name + Last name | Display name |
| Company email | Primary email |
| Company email | Username |
| Work phone | Mobile phone |
| Department | Department |
| Street address | Street address |
| Postal code | Zip code |
| City | City |

## What is required to be included in the integration?

For a user to be included in and/or created through the integration, the employee must have:

- A company email address registered in Hailey

The employee must also have one of the following employment statuses:

- **Will join**
- **In service**
- **Will leave**

### Step 3 - Setup in Hailey

Go to **Settings** - **Integrations**. Open the Okta integrations and paste the copied domain in the field **Okta domain**. Fetch your copied token from Okta and paste it in the field **Access token**. **Activate** the synchronization.

There is also an option to **decommission users without an active employment**. When enabled, employees whose employment end date has passed will automatically be deactivated in Okta. In Okta, these users will receive the status **Suspended**.

When done, click **Save**. Your integration is now up and running.

## Does the integration not apply to the entire company?

In that case, it is possible to **scope the integration**.

- Scoping the integration allows you to ensure that only employees belonging to specific **workplaces** and/or **legal entities** are included in the integration.
- It is important to configure the scope during the initial setup, as synchronization starts immediately once the integration is activated. Defining the scope from the start ensures that only the correct employees are synchronized from Hailey to Okta.
- This also makes it possible to set up multiple integrations connected to different Okta tenants or environments.

If these fields are left blank, all employees who meet the integration requirements will be synchronized.

## Common questions

**Question 1:** Why isn't the employee's Okta account being deactivated when the employment end date has passed in Hailey?

First, verify that the **Decommission employees without an active employment** setting is enabled in the integration setup in Hailey. If the setting is enabled and everything appears to be configured correctly, check whether the employee has any elevated permissions or licenses assigned in Okta. In some cases, this may prevent the employee from being automatically deactivated through the integration.

**Question 2:** How will users who already exist in Okta be matched and managed when synchronization is activated? Will duplicate users be created?

The integration identifies employees based on their **company email address**. If the email address already exists in Okta, no duplicate user will be created. Instead, the integration will recognize and match the employee to their existing Okta profile.

**Question 3:** What happens if I change an employee’s company email address in Hailey? How does it affect the integration?

If you change an employee’s company email address in Hailey, a new user profile will be created in Okta. This is because the email address is used as the unique identifier when creating the employee’s account and serves as the link between Hailey and Okta. As a result, changing the email address breaks the existing connection between the systems, causing the integration to create a new profile based on the updated email address.
