title: "Integration with Kleer - Salary and employee data"
---

Save time and reduce administrative work with Hailey’s integration with Kleer. The integration automatically creates employees in Kleer and synchronizes payroll data — helping you avoid unnecessary errors and making everyday work a little smoother.

<Tip>
  First time activating one of **Hailey's standard integrations**? Start by reading [**THIS**](/haileys-standard-integrations) guide to know what to keep in mind before you get started.
</Tip>

---

## What does the integration do?

During each synchronization, **included data** is automatically updated via **API transfer** in Kleer to match the values in Hailey, as **Hailey serves as master.**

<Note>
  **Do you also want to sync time off?** See our guide [HERE](/integration-with-kleer) for the integration with Kleer - Time off.
</Note>

## How does the integration work?

With the API transfer, a synchronization between Hailey and Kleer takes place **once an hour based on changes.** This means that:

- If any updates are made to an employees included data in Hailey, the information will be automatically updated in Kleer.

### Employee data:

| **HAILEY** | **KLEER** |
| --- | --- |
| Company Email First name, Last name Personal identity number Start date End date Work phone Street address Postal code City Country Clearing number Account number | Email Name Swedish ID number Employment date Departure date Phone Address Postcode Postal locality Country code Clearing Account number |

### Salary data:

| **HAILEY** | **KLEER** |
| --- | --- |
| Monthly salary | Monthly salary |

## What is required to be included in the integration?

For an **employee to be included** in the integration, the following is required:

- Company email
- First and last name

If an employee in Hailey has a company email that does not yet exist in Kleer, a new user will be created in Kleer. Therefore, it is important that all new employees are always created in Hailey first.

<Note>
  If an employee’s **company email is changed in Hailey,** the integration will **create a new** **profile in Kleer** with the updated email.
</Note>

For **employment** and **salary data** to be synchronized, the following is required on the employee’s profile in Hailey:

- Swedish personal identity number
- Salary types in Hailey, with each salary assigned to a salary type

Read our guide [HERE](/salary-types) on how to create salary types, and read our guide [HERE](/import-salary-changes) on how to import this information to existing salaries.

Employees with the following **employment statuses** are included in the integration:

- In service
- Leaving
- Has left

**Follow the instructions below to complete the activation of the integration.**

Before activating the integration, it is important that you **contact your contact person at Kleer**, who can provide the **required API key** for the setup. The person setting up the integration between Hailey and Kleer must also have access to an **administrator** **account** **in both systems.**

To activate the integration in Hailey:

- Go to **Settings.**
- Click **Integrations** at the bottom of the menu bar.
- Select the **Payroll** section.
- Click on **NEW Kleer** **Standard** and then **Add integration.**

Paste the **company number** and the **access token** that you **received from Kleer.** Then click on **Authenticate**.

![](https://docs.haileyhr.com/hs-fs/hubfs/image-png-May-04-2026-08-37-24-4226-AM.png?width=670&height=310&name=image-png-May-04-2026-08-37-24-4226-AM.png)

#### Synchronize employments and salaries

##### When setting up the integration, it’s important to select **one of the options below for the transfer date**. The chosen date determines the synchronization between the systems and ensures that salary and employment data from Hailey to Kleer are transferred correctly.

There are two options for selecting the transfer date, where you can choose the option that suits you best:

**Option 1:**

- The field for the transfer date in Hailey must be the **first day of the current month.** That is, if you set up the integration during the month of October, the transfer date must be 1/10.

**Option 2:**

- The field for the transfer date in Hailey must be set to a date before the first employment start date or before the first registered salary in Kleer. It is important to note that all history after this date also needs to exist in Hailey, since **Hailey is master** for the data from that date onwards.

#### Synchronize salaries

In the next step, select the salary types to be included in the integration. Please note that if an employee has multiple salaries of the same type, these will be grouped together.

- Only monthly salary is included in the synchronization between Hailey and Kleer.

![](https://docs.haileyhr.com/hs-fs/hubfs/image-png-May-06-2026-09-21-30-3739-AM.png?width=670&height=671&name=image-png-May-06-2026-09-21-30-3739-AM.png)

When all steps of the integration setup have been completed, click **Save**.

- _Does the integration not apply to the entire company? -_ Read the next step in the guide about scope **before** **you click save.**

Now that the integration is enabled, Hailey will automatically read in all users from your Kleer account who meet the requirements for the integration.You can see which/how many integrations your company has active under the Active tab in Integrations.

## Does the integration not apply to the entire company?

Then it is possible to add a **scope** for the integration!

- Setting a scope means you can choose to include only **employees assigned to a specific workplace and/or legal entity in the integration.**
- This must be configured when setting up the integration. It is **important** to do this at the initial setup, **as the synchronization starts immediately.** This ensures that only the correct employees are synced from Hailey to Kleer.

If these fields are left empty, all employees that meets the requirements of the integration will be included in the integration.

**Important information regarding employments and scope:**

- Only employments that are included in the integration will be synced to Kleer.
- If an employee has multiple employments, only those that meet the integration criteria will be included. Any new employment that does not meet the integration criteria will result in the salary being set to zero.
- For example: If the integration is limited to a specific workplace, the workplace field must be filled in for all employments that should be synced. This also applies to historical employments.

- If your company has multiple workplaces and/or legal entities in Hailey, it may be beneficial to create separate integrations with Kleer for different/multiple Kleer accounts.

## Common questions

<AccordionGroup>
  <Accordion title="What could be the reason why an employee isn't syncing to Kleer?">
    Start by checking that the integration is enabled, that the employee meets the requirements for syncing, and that they belong to an organizational unit included in the integration (if you're using organizational scoping). If the employee's organizational unit is incorrect, they won't be synced to Kleer.
  </Accordion>

  <Accordion title="I received the following email from Hailey. What does it mean?">
    ![](https://docs.haileyhr.com/hs-fs/hubfs/image-png-Jun-02-2025-01-21-50-5511-PM.png?width=582&height=469&name=image-png-Jun-02-2025-01-21-50-5511-PM.png)

    This means that the employee was deactivated in Kleer and then reactivated, for example after being rehired in Hailey.
  </Accordion>

  <Accordion title="An employee's salary has been set to zero in Kleer. What could be causing this?">
    This is usually caused by the employee's current employment not belonging to an organizational unit included in the integration. Update the employee's employment with the correct organizational unit, and the salary will be updated in Kleer during the next synchronization, which runs every hour. The same applies to any historical employments.
  </Accordion>

  <Accordion title="Why isn't an employee's end date being updated in Kleer?">
    If the employee's end date has already passed, it won't be synced retroactively. In this case, you'll need to enter the termination date manually in Kleer.
  </Accordion>

  <Accordion title="What happens if an employee does not have a Swedish personal                     identity number when they are synced from Hailey to Kleer?">
    If an employee does not have a Swedish personal identity number registered in Hailey, their first name, last name, and email address will still be synced to Kleer. However, the employee's employment record will need to be set up manually directly in Kleer.

    _If you have any questions regarding the integration, please contact Hailey support._
  </Accordion>
</AccordionGroup>
